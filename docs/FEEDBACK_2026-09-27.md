# Hands-on feedback: installed .deb against prod (2026-09-27)

Dictated by the user after installing the .deb and using Fathom against the production cluster.
Numbers are stable IDs used in commits and specs ("feedback #12"). Code locations come from a
read-only investigation the same day. Verify them before relying on them.

## Group 1: bugs (start now, independent)

1. **Reload kubeconfig does nothing (packaged build).** The button is wired
   (`FirstRunState.tsx:92` → `Initialize` → `kube::load_and_send_contexts_full`). But the .deb
   desktop entry is `Exec=fathom-desktop` and nothing imports the login-shell env, so a
   `KUBECONFIG` exported in `.bashrc`/`.zshrc` is invisible and so is the user's `PATH` (which
   breaks exec credential plugins). The button also gives no feedback when the result is
   unchanged. Fix: import the login-shell env at startup, show the resolved kubeconfig paths,
   and confirm or report the outcome of a reload.
2. **Pod logs load forever at laptop width and up.** The backend log stream is a singleton
   (`src/backend/pods.rs:394` stops the previous one on every `StartPodLogs`) and every
   `PodLogsTab` sends `StopPodLogs` when it unmounts. The dock Logs tool, the inspector Logs tab
   and the tools sheet therefore kill each other's streams. The logs view also spins forever when:
   - a quiet pod never delivers a first chunk (the stream entry is only created on the first
     `PodLogsChunk`)
   - the stream errors (reported only in a toast; `StreamClosed` is mis-kinded as `exec`)
   - the pod-details read fails

   Separately, `SlotGrid.tsx:44` keys the whole row on the width class, so crossing 1920 or 2560
   px remounts every slot. Fix: a stream id per view, opened and closed events, empty and error
   states, and no remount on a width-class change.
3. **Uneven panes on ultrawide.**
31. **Metrics discovery misses Prometheus in the `monitoring` namespace on prod.** This
    follows up on spec 041. Scan common namespaces, service labels and ports, and the Prometheus
    Operator's objects, with a manual endpoint as the fallback.
32. **Metrics failure shows a raw 404 page followed by a 503.** Show a short readable status with
    the raw response behind "details". Likely cause: a wrong service-proxy path, or a service
    with no ready endpoints.
36. **Custom resources don't load** (clicking a CRD such as `Order` never shows instances).
40. **Secret Reveal fails** with "values not transferred / backend never sent secret values".
    Keep the design where values are fetched only on Reveal and never cached.
24. **Linter re-runs every time you navigate back.** Cache results per context, reuse a run that
    is already going, and re-run only when resources change or the user asks for a refresh.
27. **Port-forward local ports start at 1024.** Start at 10000 and skip ports already in use.

## Group 3: cascading layout

6. / 7. Slot 1 is the sections nav. Slot 2 is the selected section. Slots 3 to 6 stay empty until
   the user drills in, then fill as they cascade. Clicking a section on a wide screen should
   spread the next 3 or 4 levels across it automatically. The current wide and ultra profiles
   prefill extra list, Overview and Flux slots, which is the opposite of this.
8. Keep the current behaviour on small windows.

28. / 29. / 30. / 34. A Fleet tab in the context tab strip, leading to its own Fleet dashboard.

    Open question for #29, the "pre-processing screen": a setup step for choosing and connecting

33. Keep each cluster's connection and integration state across views, so switching views does
    not re-discover it (Hubble → Federation showed prod as disabled until it reloaded).
35. A "Request integration" button on custom resource views opens a pre-filled GitHub issue.
37. A CRD browser: a table per CRD built from its own columns, plus owner and reference links.
39. Secrets: a Values tab with masked keys, per-key reveal and copy, decoding, and

    bubblewrap or Landlock.
50. / 51. The Overview can be opened as a standalone view. Pop out views into their own Tauri
    windows. This needs backend events broadcast to every window and subscriptions tracked per
    window.
52. A Feedback button at the far right of the status bar opens a modal that leads to a
    pre-filled GitHub issue. Add `.github/ISSUE_TEMPLATE/`.
53. A Support button opens a modal with GitHub Sponsors, Ko-fi and PayPal (from `FUNDING.yml`).
    Never a nag popup. Open question: add the wishlist link to Fathom's `FUNDING.yml` too?
