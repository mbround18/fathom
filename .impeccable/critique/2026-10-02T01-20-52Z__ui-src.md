## Design Specificity Verdict

GENUINELY SPECIFIC — could not be lifted onto another product without breaking.

Structural proof: layout/cascade.ts implements a Miller-column chain (pushStep/truncateAt/slotsFor)
where selecting a non-terminal row drops every column to its right, and widening the window
re-reveals earlier steps instead of re-flowing. ultra.png shows six live columns. That is
`kubectl get` -> `describe` -> follow-the-owner-reference made spatial; the shape only pays off when
objects have owner/controller graphs. Numbered panes (01 SECTIONS, 02 PODS) give an operator an
addressable column name. --radius: 0 on every token, --font-sans aliased to JetBrains Mono,
CJK section glyphs as peripheral scan anchors — all authored, coherent.

Strongest signal is copy: the node-shell confirm discloses privileged/hostPID/hostNetwork/hostIPC,
the /host mount and the 240-minute TTL unprompted; the setup screen says "Your kubeconfig is not
changed."

Category-interchangeable where it slips: the empty cascade placeholder renders twice identically in
four screenshots (cold start ~55% empty at 4K); the Identity dialog is sentence-case with two
primary buttons in one scroll; the topology graph is the default force-directed blob with no legend.

Deterministic scan: contributed nothing (see caveat 1).

## What's Working

1. tests/unit/contrast.test.ts is a contract, not a checkbox — parses tokens.css, resolves var()
   chains, asserts 4.5:1/3:1 per variant, 201/201 passing in 380ms. --border carries an inline
   comment admitting the design intent composited to 2.36:1 and that L was raised to 74% to pass.
2. The decorative layer was designed as removable: effects.css scopes itself to "chrome,
   transitions, and empty/error states only: never table rows, log lines, or YAML", which is why
   prefers-reduced-motion (effects.css:141-148, * + !important) and html[data-effects=off] are
   one-liners. index.css also ships prefers-contrast: more, forced-colors: active with per-selector
   forced-color-adjust, and a 12px type floor.
3. ResourceTable.tsx uses the right grid pattern: role="grid", aria-rowcount/colcount, aria-sort
   per header, aria-activedescendant with roving tabIndex={-1} — activedescendant rather than
   moving DOM focus is what keeps arrow-key scanning at terminal speed.

Also measured clean: 118 aria-label, 44 focus-visible sites, zero unlabelled icon-only buttons,
zero tab-reachable elements with suppressed-and-unreplaced focus rings, alt=0 correct (no <img>
elements exist; all 3 <svg> handled with role="img"+aria-label or aria-hidden).

## Priority Issues

### [P1] Tailwind alpha modifiers drop 38 borders to 1.7-1.9:1, below the committed AA floor
Measured in gamma space (how browsers blend). --border is oklch(74% ... / 55%); a /60 modifier
multiplies rather than replaces:

| effective alpha | over --card | over --background | over --muted |
|---|---|---|---|
| 55% (token) | 3.16:1 | 3.18:1 | 3.06:1 |
| 33% (/60, 18 uses) | 1.90:1 | 1.86:1 | 1.92:1 |
| 27.5% (/50, 14 uses) | 1.68:1 | 1.63:1 | 1.70:1 |

38 usages total (18x /60, 14x /50, 3x /80, 3x /40). contrast.test.ts resolves tokens but cannot see
utility-level alpha, so none is covered. SC 1.4.11 applies where a boundary is REQUIRED to identify
a control, so form-control and checkbox sites are breaches while decorative dividers are
defensible. Separately: Input is `border-input bg-transparent`, i.e. --border at 3.16:1 is the ONLY
boundary a text field has — passing by 0.16, which is why the Identity dialog's inputs read as
near-invisible rectangles.
FIX: add a contrast.test.ts suite that greps .tsx for (border|text|bg)-[a-z-]+/\d+ and composites
against --card/--background/--muted; promote control boundaries to an opaque --control-border token
at >=3:1 and reserve alpha variants for decoration. Command: /impeccable audit

### [P1] aria-selected on the grid row means the wrong thing
ResourceTable.tsx:562 sets aria-selected={open} ("open in the inspector") while the grid declares
aria-multiselectable="true" (:380) and real selection lives in a sibling role="checkbox" (:645).
A screen-reader user hears "selected" for the row they merely opened and hears nothing for the rows
they actually checked — then confirms a bulk delete listing objects they were never told they had
selected. Committed AA floor failing on the highest-stakes path; invisible to the contrast gate.
FIX: aria-selected tracks checkbox state; express inspector-open with aria-current="true".
Command: /impeccable harden

### [P1] Delete does not honour "earn a mutation before making it"
DELETE 3 PODS is armed on first paint — no typed confirmation, no manifest, no dry-run, no backup,
no post-delete verification — and closes with "It cannot be undone." Scale, two screens away, does
it properly. Compounding: Delete is a bare unmodified key at list scope (lib/shortcuts.ts:27,
guarded only by isTypingTarget), so a 12-row selection is two keystrokes from an irreversible write.
The SRE persona is the one PRODUCT.md says is never traded away.
FIX: add a severity axis to ConfirmDialog.tsx; for `irreversible` require typing the object name or
count, add Show manifest / Dry run reusing the YAML view, and replace the dialog with a verification
result on success. Require a modifier on the Delete binding. Command: /impeccable harden

### [P2] Two surfaces named LOGS, one permanently empty
Inspector LOGS tab streams in a ~600px column while the bottom dock, also labelled LOGS, says
"CHOOSE A POD". At ultra the empty dock eats ~30% of a 1600px-tall viewport. Neither has a level
filter, follow/pause, wrap or search, and level=warn renders identically to level=info.
FIX: pick one surface; the other focuses it rather than duplicating. Auto-collapse the dock to its
28px tab strip when empty. Add level colourisation and follow/pause. Command: /impeccable layout

### [P2] graphTheme.ts holds 26 hard-coded hexes outside the design system and cannot follow the theme
Self-documents the reason ("cytoscape cannot parse the oklch tokens"). Contrast is fine (labels
6.25:1-13.35:1, edges 3.74:1 dark / 3.17:1 light). But paletteFor = (isDark: boolean) tracks
light/dark only, so the graph cannot follow [data-accent="magenta"] (accent pinned to cyan #3ef2ff)
and is unreachable by prefers-contrast: more, which only redefines custom properties. One value has
already desynced: fg '#e6ecff' vs --foreground '#d6f6ff'. TopologyCanvas.tsx shows the right
pattern — reads live CSS vars with a hex only as last-resort fallback.
FIX: resolve tokens at runtime via getComputedStyle, keyed on accent and contrast preference.
Command: /impeccable colorize

## Questions to Consider

1. If the cascade's empty slots were a rail instead of a room, would you need the bottom dock at
   all? The reclaimed ~1150px is exactly where a full-width log stream belongs.
2. What would delete look like if it were built by whoever wrote the node-shell dialog?
3. Should the inspector tab strip be a tab strip? DETAILS/YAML/EVENTS are representations of one
   object; LOGS/TERMINAL/SHELL/FORWARD are live sessions whose state should survive navigation.
4. The contrast test proves tokens are legible. What proves the composed screen is? A Playwright
   pass sampling computed colour at the painted pixel for every [data-slot] would catch the alpha
   stacking, the disabled states and the scanline overlay at once.
5. The detector returns zero findings on input designed to trip it. How much design confidence has
   been resting on that exit code?
