# Protocol Contract: Certificates (cert-manager) Pane

New additions to `src/protocol/v1/`, all read-only (classified alongside `RefreshFlux` /
`SelectFluxResource` in `mutation.rs`'s non-mutating arm).

## Commands (`BackendCmd`, `src/protocol/v1/cmd.rs`)

```rust
/// Rescan cert-manager CRDs and Certificates now (dashboard aggregate), same
/// shape as RefreshFlux.
RefreshCertManager,

/// Resolve one Certificate's lifecycle chain (Certificate -> CertificateRequest
/// -> Order -> Challenge), read-only, on-demand — same shape as SelectFluxResource.
SelectCertificateChain {
    namespace: String,
    name: String,
},
```

Round-trip tests (mirrors `select_flux_resource_roundtrip`):
- `refresh_cert_manager_roundtrip`
- `select_certificate_chain_roundtrip`

## Events (`BackendEvent::System`, `src/protocol/v1/event.rs`)

```rust
/// cert-manager CRD detection + Certificate list (dashboard aggregate).
CertManagerOverviewUpdated(CertManagerOverview),

/// Resolved lifecycle chain for one Certificate.
CertificateChainUpdated(CertificateChain),
```

## Section routing (`src/protocol/v1/route.rs::section_keys`)

```rust
pub fn integrations_cert_manager() -> SectionKey {
    SectionKey::new("integrations/cert-manager")
}

pub fn certificate_chain() -> SectionKey {
    SectionKey::new("integrations/certificate-chain")
}
```

`mutation.rs::section_for` routing:
- `C::RefreshCertManager => section_keys::integrations_cert_manager()`
- `C::SelectCertificateChain { .. } => section_keys::certificate_chain()`

Both commands join the existing non-mutating match arm (alongside `RefreshFlux`,
`SelectFluxResource`) — no new mutation classification branch.

## Backend command handling (`src/backend/cmd/integrations.rs`)

```rust
BackendCmd::RefreshCertManager => refresh_cert_manager(state, sender).await,
BackendCmd::SelectCertificateChain { namespace, name } =>
    select_certificate_chain(state, sender, namespace, name).await,
```

`refresh_cert_manager` calls `cert_manager::scan_cert_manager(&client)` and emits
`CertManagerOverviewUpdated`, exactly mirroring `refresh_flux`/`scan_flux`.

`select_certificate_chain` calls `cert_manager::resolve_chain(&client, &namespace, &name)` and
emits `CertificateChainUpdated`, exactly mirroring the `SelectFluxResource` handler in
`src/backend/cmd/resources.rs`.

## Background poll (`src/backend/sync.rs`)

```rust
pub(super) async fn ensure_cert_manager_poll(
    state: &mut BackendState,
    sender: &Sender<BackendEventEnvelope>,
) { /* identical shape to ensure_flux_poll */ }

async fn poll_cert_manager_overview(/* identical shape to poll_flux_overview */) { .. }
```

Wired into `WatchTasks` (`src/backend/state.rs`) as `cert_manager_poll_task`, aborted in
`WatchTasks::abort_all` alongside `flux_poll_task`/`hubble_poll_task`, and started from the same
call site that currently calls `ensure_flux_poll`/`ensure_hubble_poll` on connect.

## Frontend contract

- `ui/src/protocol/generated/CertManagerOverview.ts`, `CertificateSummary.ts`,
  `CertExpiryState.ts`, `CertReadyState.ts`, `CertificateChain.ts`, `ChainStage.ts`,
  `ChainStageKind.ts` — generated by the existing ts-rs build step, no manual edits.
- `ui/src/store/index.ts`: new `certManager: { overview?: CertManagerOverview; chain?: CertificateChain }` slice, alongside `flux`/`hubble`.
- `ui/src/store/handlers/system.ts`: ingest `CertManagerOverviewUpdated` → `certManager.overview`, `CertificateChainUpdated` → `certManager.chain`.
- New store actions `refreshCertManager()` (`send({ type: 'RefreshCertManager' })`) and
  `selectCertificateChain(namespace, name)` (`send({ type: 'SelectCertificateChain', namespace, name })`), mirroring `refreshFlux`.
- `ui/src/components/panels/CertManagerPanel.tsx`: registered in `PaneHost.tsx`'s tool switch as
  `pane.tool === 'certManager'`.
- `ui/src/resources/certificate-resource.tsx`: `ResourceDescriptor` so a chain stage's
  Certificate/CertificateRequest/Order/Challenge can be opened in the Inspector, following
  `flux-resource.tsx`'s reachable-only-via-click-through pattern (no navigator entry).
